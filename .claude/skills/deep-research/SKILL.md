# Deep research — nms-exporter instance

The invariant method is the shared skill (`~/.claude/skills/deep-research/SKILL.md`).
This file supplies this repo's parameters. Read, in order:

1. `research/index.md` — charter, evidence ladder, review lenses, privacy.
2. `knowledge/meta/conventions.md` — frontmatter contract and trust entries.
3. The question file(s) the brief answers, in `research/questions/<slug>.md`.
4. The concepts already in `knowledge/` on the topic, so the run extends
   rather than re-derives.

## Parameters

| Parameter | Here |
|---|---|
| Charter | `research/index.md` |
| Question register | `research/questions/` (index generated by `scripts/research-index`) |
| Raw store | `research/sources/{game-data,web,measurements}/`, plus each run's `raw/` |
| Knowledge bundle | `knowledge/` (`mechanics/`, `data-locations/`, `tools/`) |
| Review lenses | version laundering, data-is-not-behaviour, mode and platform, mod pages as evidence, absence in the data |
| Domain tooling | `scripts/nms-pak` (find/get/grep/cite game files), `scripts/nms-data` (extracted tables), `scripts/research-fetch` (web pages), the exporter's `/json` and `/diff` and `scripts/nms-decode-save.py` (saves), `scripts/okf-lint` |

The scope field that plays the part of "population" is **`builds`**: the Steam
build id (installed build from `appmanifest_275850.acf`; `nms-pak` prints it)
plus, for community material, the patch or date the source was written
against. A claim with no build or date is not usable as current.

## Small questions do not need a run

One gap, one or two sources: answer it in-session. Store the sources with the
tools, write or update the concept with `generated: {by: "machine:session"}`
and `verified: []`, update the question file, `scripts/research-index`,
`scripts/okf-lint`, a line in `knowledge/log.md`. A full run is for questions
that need fan-out or an adversarial review before anything is relied on.

## Runs

Brief first, agreed with Bob, in `research/runs/YYYY-MM-DD-slug/brief.md`:
the question, the build and mode scope, what is already known (link concepts),
what decision it changes (exporter, planner, play, mod), and depth
(`orientation` 1-2 sub-questions, `standard` 3-4, `deep` 5-6).

Run with `Workflow({scriptPath: ".claude/skills/deep-research/run-workflow.js", args})`,
`args` kept beside the brief as `args.json`:

| Arg | Carries |
|---|---|
| `run`, `date` | `research/runs/<run>` and the run date |
| `build` | the installed Steam build id |
| `house_extra`, `plan_extra`, `review_extra`, `synth_extra` | run-specific additions (pass every one, even empty) |

Check usage before every dispatch (commute MCP `claude_usage`): at 85% of the
5-hour window dispatch nothing new and checkpoint; at 90% commit what exists.

## Promotion (from the orchestrating session, never inside the workflow)

Surviving findings go into `knowledge/` with the reviewer's `evidence_level`
unaltered, `status: draft`, `builds`, `stale_after`, and
`verified: [{by: "machine:reviewer", at: <date>, run: <run>}]`. Never
`human:bob`. Then question files (`status`, `runs`, `answered_by`),
`scripts/research-index`, `scripts/okf-lint`, `knowledge/log.md`, and
`promoted.md` in the run directory saying what landed and what did not.

## Measurements

Many mechanics here are hardcoded and only measurable. A measurement is a
file in `research/sources/measurements/` with: build, date, method (which
saves, which in-game action), the raw readings as a table, and what was not
recorded. Saves are the best instrument: the exporter keeps the last 48
snapshots and `/diff?against=N` gives save-to-save differences. Ask Bob to do
the in-game action; never guess readings.
