# Research charter

## What this is for

A compendium of how No Man's Sky actually works, built so that answers to
"how does X work / what's the number / where does the game keep it" are looked
up once, sourced, and reused — by Bob at the game, by the exporter and its
planner, and by whichever Claude session is asked next.

The questions come from play: the device money loop (Stasis Devices, Fusion
Ignitors, Gold), farms and refiners, base and freighter layout, trading. A
finding is most valuable when it changes one of:

- **a play decision** (what to build, where to sell, how to lay out a farm),
- **the exporter or planner** (a rate, cap or formula it projects with),
- **a mod Bob builds** (which file and field to change).

Reference facts that change none of these are still worth keeping, but they
are not what a run is for.

## Where things live

| Path | What |
|---|---|
| `research/questions/` | One file per open question (`type: Question`). `index.md` is generated by `scripts/research-index`. |
| `research/runs/YYYY-MM-DD-slug/` | One directory per run: `brief.md`, `args.json`, `plan.md`, `raw/`, `review-*.md`, `synthesis.md`, `promoted.md`. |
| `research/sources/game-data/<build>/` | Excerpts of the game's own files, stored by `scripts/nms-pak cite` with build, pak, path and line range. |
| `research/sources/web/` | Web pages stored verbatim as text by `scripts/research-fetch`, with URL, date and hash. |
| `research/sources/measurements/` | In-game measurements and save-derived numbers: method, raw readings, build. |
| `knowledge/` | The compendium: one concept per file, OKF-style frontmatter. See `knowledge/meta/conventions.md`. |

## The evidence ladder

Strongest first. The reviewer, never the finder, assigns the level.

1. **game-data** — the installed build's own files say so (excerpt cited).
2. **code** — the executable does so: a runtime hook or disassembly, method recorded.
3. **measured** — measured in game or across saves, method and readings stored.
4. **official** — Hello Games patch notes or statements.
5. **community-measured** — someone else measured it and published the method.
6. **community-claim** — wiki, forum, video or mod page without a method.

A game-data value is not yet a behaviour: "Radius is 6.0" is game-data; "Harvest
All reaches 6 m around the room's floor" needs code or a measurement too.
Concepts keep the two apart.

## Review lenses (on top of the skill's universal ones)

- **Version laundering** — the most likely error. A wiki line written before
  Origins, Frontiers, Worlds or Cosmos cited as current. Every claim names the
  build it was observed on; community claims carry the page date or patch.
- **Data is not behaviour** — a field in a table is not proof the code uses it
  that way (the trading cost table exists and is unused).
- **Mode and platform** — difficulty presets, custom settings, expeditions,
  permadeath and console builds change numbers. Default scope is PC, Normal
  preset, the main save.
- **Mod pages as evidence** — a mod's description says what its author
  intended, for the version they built against.
- **Absence in the data** — "not in the paks" needs the `nms-pak find`/`grep`
  that would have found it, stored as a census; until then it is "not found
  in the files we unpacked", and "hardcoded" is a hypothesis.

## Staleness

Every game update can change any of this. Game-data, code and measured
concepts carry `builds:` and `stale_after: next-build`; `scripts/okf-lint`
flags them when the installed build moves on. Community material carries a
date.

## Privacy

Saves hold Bob's player and base names and galactic addresses. Never put them
in a web query or a stored source; describe the situation generically.

## Running research

Deep runs follow `.claude/skills/deep-research/SKILL.md` (this repo's
instance of the shared skill). Small, single-gap questions can be answered in
a session directly — store the sources, write the concept, update the
question, log it. Either way: **if a claim cites it, it is stored**.
